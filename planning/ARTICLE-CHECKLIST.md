# 글 하나의 공통 체크리스트

새 글을 시작할 때 이 목록을 해당 컬렉션 문서의 작업 항목 옆에 두고 진행합니다.
컬렉션 문서에는 글마다 고유한 작업만 적고, 모든 글에 공통인 작업은 여기에만 둡니다.

## 착수

- [ ] 이 글이 답하는 질문을 독자의 말투로 2~5개 적었다
- [ ] 다룰 범위와 다루지 않을 것을 정했다
- [ ] 기준 버전과 배포 형태(self-managed, ECH, ECE, ECK, Serverless)를 정했다
- [ ] 같은 컬렉션이나 다른 컬렉션의 기존 글과 겹치는 부분을 확인하고, 어느 글에 둘지 정했다

## 조사

- [ ] 컬렉션 문서의 "공식 출처"를 모두 읽고, 글에서 쓸 사실을 출처와 함께 메모했다
- [ ] 기능 상태(GA, preview, planned, 배포 형태별 차이)를 공식 문서로 확인했다
- [ ] 라이선스 조건이 걸린 기능은 공식 subscription 페이지나 문서 기준으로 확인했다
- [ ] "확인할 사실" 목록을 모두 확인했거나, 확인하지 못한 항목에 "확인 필요"를 붙이기로 했다
- [ ] 참고한 내부 자료가 있다면, 글에 쓸 내용을 공개 출처(A~D)로 다시 확인했다. 확인하지 못한 내용은 뺐다

## 실험 (labs가 있는 글)

- [ ] `labs/<collection>/<slug>/README.md`에 목적, 환경, 버전, 실행 방법을 적었다
- [ ] synthetic data 생성 코드와 설정 파일을 같이 넣었다. 실제 고객 데이터나 그로부터 유도한 값은 쓰지 않았다
- [ ] 측정은 최소 2회 이상 반복하고, 편차를 같이 기록했다
- [ ] 결과 표에 실측 값과 예시 값을 구분했다
- [ ] 외부 데이터셋을 쓰면 라이선스를 확인하고 출처를 적었다

## 초안

- [ ] `templates/use-case.md`를 복사해 `draft: true`로 시작했다
- [ ] 맨 위 `기준과 전제`에 기준 버전, 확인 날짜, 기능 상태, labs 경로를 적었다
- [ ] 현장 경험은 업종 수준으로만 썼고, 특정 환경을 알아볼 수 있는 조합이 없다
- [ ] 제 판단은 "해석", 확인하지 못한 내용은 "확인 필요"로 표시했다
- [ ] "데이터에 따라 다르다"로 끝나는 문장이 없고, 조건과 결과를 같이 보여 준다
- [ ] 흐름도는 mermaid 코드 블록으로 썼다

## 발행 전 재검증

- [ ] 본문의 사실 문장을 처음부터 끝까지 공식 출처와 다시 대조했다 (이전 조사 결과를 믿지 않고 새로 확인)
- [ ] 기본값, 제약, 기능 상태가 발행 시점 최신 문서와 일치한다
- [ ] 모든 링크가 열리고, 링크한 페이지에 인용한 내용이 실제로 있다
- [ ] 수치마다 출처(공식 문서, labs 실측, 예시)가 분명하다
- [ ] 사내 정보, 고객 정보, 발표 전 정보가 없다
- [ ] em dash와 번역투 표현을 정리했다
- [ ] 로컬에서 `npm run build`가 통과한다

## 발행

- [ ] `draft: true`를 지웠다
- [ ] 컬렉션 `index.md`의 구성 표와 자주 받는 질문을 갱신했다
- [ ] `planning/ROADMAP.md`와 컬렉션 문서의 상태와 체크박스를 갱신했다
